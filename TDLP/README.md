# TDLP, LMP, and TLON

Three independent Node.js 20+ ESM packages with TypeScript declarations and no third-party runtime dependencies:

| Package | Purpose |
| --- | --- |
| `@deadbord/tlon` | Strict printable-ASCII TLON encoding and decoding |
| `@deadbord/lmp` | LMP packet codec, scoped resource IDs, application dispatcher |
| `@deadbord/tdlp` | UDP client/server, encryption, handshake, pipelined batches, retries |

All source is executable JavaScript; no build step is required. No backend or frontend files are used at runtime.

## Install and test

From this directory:

```sh
npm install --ignore-scripts
npm test
node examples/roundtrip.js
```

The root workspace links the three packages. Scripts in another project can install them as local packages:

```sh
npm install /absolute/path/TDLP/tlon /absolute/path/TDLP/lmp /absolute/path/TDLP/tdlp
```

Each package can be packed independently with `npm pack` from its own directory. For distribution, publish TLON, then LMP, then TDLP to your registry, or supply all three tarballs to `npm install`. Dependencies use package names and semver, not repository-relative imports. Consumers do not need the root workspace.

## Use

```js
import { Client, Server } from '@deadbord/tdlp';
import { Dispatcher, Scope, Action, Response, resourceId, newActionId } from '@deadbord/lmp';
```

`new Server({ privateKey, authorize, dispatcher })` accepts an RSA private key as a PEM string, Buffer, or Node `KeyObject`. `await server.listen(port, host)` returns its bound address. It uses IPv4 UDP and defaults to loopback. Call `await server.close()` to release it.

`authorize({ sessionKey, resources, packetCount, remote })` must return `null` to reject, or `{ principal: 'stable-authenticated-user-id', ...applicationContext }` to accept. Verify permissions for every resource before accepting. Session keys are opaque printable ASCII values. Resource entries supplied to this callback are `{ scope, id: bigint }`.

Share one `Dispatcher(handler)` across server connections. The handler receives an LMP action plus `{ principal, resources, remote, connectionId, ...applicationContext }` and returns `{ code, version?, payload? }`. The dispatcher adds response identity fields. It converts handler exceptions or invalid/oversized responses into a generic `NOPE`, without exposing internal exceptions.

**The application handler owns database operations, transaction boundaries, version comparison, field validation, and per-action authorization.** This includes permission levels for `UPDATE_PERM`, authorization for `CREATE` under an allowed parent resource, and returning a new scope ID in CREATE's application-defined DONE payload. TDLP rejects actions targeting IDs outside INIT's resources, except CREATE (whose scope ID is necessarily zero). CREATE always needs the handler's parent-resource permission check.

```js
const client = new Client({ host: '127.0.0.1', port, publicKey });
try {
  await client.connect({
    sessionKey: 'application-session-key',
    resources: [resourceId(Scope.Task, 42n)],
    packetCount: 1,
    payloadTimeoutMs: 1000,
  });
  const result = await client.request({
    response: false, scope: Scope.Task, scopeId: 42n,
    code: Action.Obtain, actionId: newActionId(), payload: [['name']],
  });
  console.log(result);
} finally {
  client.close();
}
```

One Client instance handles one connection and one batch. `packetCount` must be positive and match the intended number of actions. Calls to `request()` can run concurrently; each resolves with its matching LMP response. Send all actions promptly after `connect()`. The caller closes after collecting responses. A fresh connection requires a fresh Client. Neither session keys nor action UUIDs are generated by TDLP; preserve an action UUID when retrying the same logical action across connections.

Clients and servers emit `invalidPacket` with an Error for malformed packets. Servers emit `networkError` for UDP failures; clients emit `close`. Invalid datagrams are ignored without advancing handshake or request state.

## Wire decisions supplementing spec.zip

- Integers use big-endian encoding. LMP scope IDs use `bigint`, avoiding JavaScript precision loss. An INIT resource is the decimal string of `(scope << 64) | id`; reserved scope 3 is rejected.
- TDLP's message code occupies the high nibble; the low nibble is zero. LMP's high bit denotes response, bits 6–5 denote scope, bits 4–2 denote operation, and bits 1–0 are zero.
- Plain packets: connection ID (4 bytes), packet ID (2), message byte (1), payload. The initial client HI uses connection ID zero; the server HI uses its assigned ID in both the header and TLON payload.
- KEY uses RSA-OAEP/SHA-256 over TLON containing four scalar entries: `aes256`, a 64-digit hexadecimal AES key, and two distinct 16-digit hexadecimal direction prefixes. The deployment supplies the trusted server public key. RSA keys must be large enough for this payload (2048-bit RSA works).
- Encrypted packets: connection ID (4), packet ID (2), independent encryption counter (2), ciphertext. The message byte and payload are encrypted with AES-256-CTR. The IV is prefix (8), encryption counter (2), reserved zero (2), block counter (4). Counters start at zero independently in each direction. Retries preserve the entire original datagram. A counter value cannot be reused for different data; the cipher refuses to wrap. Counter exhaustion terminates the connection; start a fresh connection with fresh keys.
- ENCRYPT and subsequent messages use AES, except BUGOFF for an unknown/previously closed connection ID: no key remains, so that response is plaintext. An established client accepts that exact seven-byte BUGOFF form. HI and KEY remain plaintext-header packets; KEY's payload is RSA ciphertext.
- The epoch is `2026-10-18T06:00:00Z`; server HI expiration is seconds since that epoch. INIT's payload timeout is a duration in milliseconds.
- LMP's UUID uses 16 raw bytes. The version is present only on UPDATE, DELETE, UPDATE_PERM, and DONE. CONFLICT carries two scalar TLON entries for expected and current uint32 versions, with no binary version field. REJECT has no payload.
- TLON is `string[][]`. An outer entry terminates with byte `0x1f`, and inner values separate with `0x1e`. `[]` encodes an empty payload; `[['']]` encodes one empty value. Data is ASCII `0x20`–`0x7e`; there is no escaping or Unicode encoding. Each entry requires at least one value. The decoder rejects invalid bytes and unterminated entries.
- The LMP payload limit is exactly 500 bytes, excluding headers. Task CREATE uses one scalar name. UPDATE, OBTAIN and UPDATE_PERM validate property tuple shapes; database-specific properties and Board/List CREATE payloads remain application-defined because the source spec does not define them. DONE payload schemas are also application-defined.

## Reliability and limits

The client retries each handshake stage and unanswered action at `retryMs` intervals (default 250 ms), up to `maxRetries` retransmissions (default 8). The server caches exact replies so duplicate control packets and actions do not repeat work. Receiving all expected action IDs ends missing-packet checks; slow application handlers are still awaited separately.

At each INIT payload timeout, the server requests missing IDs with HUH, splitting long lists into bounded datagrams. It performs at most `maxRetries + 1` HUH rounds, then expires the incomplete connection. Clients also count HUH-triggered resends against their action retry budget. No segmentation is used for an individual LMP action or response.

Server defaults: 60-second connection lifetime, 1,000 simultaneous connections, 1,024 actions per connection, and a maximum INIT payload timeout of 60 seconds. Configure these with `connectionTtlMs`, `maxConnections`, `maxBatchSize` (up to the protocol's 65,535 IDs), and `maxPayloadTimeoutMs`. Large batches must leave encryption-counter capacity for control packets. Invalid-ID BUGOFF replies are limited to one per second per remote endpoint and connection ID, with a bounded rate-limit table. Closed connections have their state discarded.

Dispatcher action IDs are namespaced by authenticated principal. It deduplicates concurrent calls and stores serialized responses, rejecting a reused UUID with changed request contents. The default cache retains entries for the dispatcher's lifetime and rejects new work at 10,000 entries rather than evicting completed actions and repeating their side effects. Configure `maxEntries` or a finite `ttlMs` if your application accepts a shorter deduplication window. The in-memory cache cannot preserve exactly-once behavior across process restarts; durable applications should supply a dispatcher backed by an atomic database operation and persistent action journal. Network timeouts cannot prove whether a mutation committed.

AES-CTR intentionally has no integrity verification, as specified. Ciphertext and plaintext routing fields can be modified by an attacker; replay checks and validation do not provide authentication. This implementation does not add a MAC or claim authenticated transport security.
